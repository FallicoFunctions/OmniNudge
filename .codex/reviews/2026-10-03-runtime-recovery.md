## Additional techniques

None beyond the existing instruments. Native replacement-device loss is covered by B5/F1 and repeated below.

RR-001 — P2; D2/F4; queued restoration after disposal. Native timer ran graphics rebuild and announced restoration on disposed engine. Fix: await the deferral inside the adapter and check disposal again. Regression: webGpuRecoveryLifecycle disposed-between-init-and-rebuild; negative control RR-001-reverse.patch removes only the second check, compiles then fails unexpected rebuild call.

RR-002 — P2; D2/E3; resource rebuild error escapes asynchronous timer. Fix: own the awaited resource stage and route its rejection to onFailure without restored publication. Regression: webGpuRecoveryLifecycle queued failure; RR-002-reverse.patch removes error reporting, compiles then fails expected callback assertion. Original native timer failure is also captured in pass1-queued-before.log.

RR-003 — P2; F1; overlapping replacement device initialization. Fix: serialize initialization, coalesce latest queued loss, preserve lost render gate, discard queued recovery on dispose. Regression: serialized second loss; RR-003-reverse.patch removes busy guard, compiles then fails unexpected second initializer call.

RR-004 — P2; G1; delayed-initialization regression released its promise before the native task could expose a missing await. Fix: keep it unresolved across a full task boundary. Regression: existing wait test; await-reverse.patch omits await and now compiles then fails geometry/pipeline events expected empty. This is a test-strength issue rather than another production defect.

RR-005 — P2; B5/F1; replacement device lost during initialization still produced a transient restored notification on that destroyed device. Actual native WebGPU reloss probe shows two losses/two restored and explicit destroyed-device publication (pass1-reloss-before.txt). Fix: skip superseded resource rebuild/publication while carrying saved depth state into queued initialization. Regression: serialized second loss now requires only one valid rebuild/notification and preserved depth state; RR-005-reverse.patch removes superseded-device checks.
